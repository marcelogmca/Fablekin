### INSTRUCTIONS:
1. Analyze the CURRENT NARRATIVE to see if the party is moving, has arrived at a new location, or stayed put.
2. Characterize the movement into one of three statuses:
   - "STAYED": The party is still at the same anchor node, even if moving to a specific spot within it (e.g. from the city gates to the tavern). **CRITICAL: Use this if the narrative is purely descriptive or movement is local.**
   - "ARRIVED": The party has reached a new anchor node or a significantly distant area.
   - "TRANSIT": The party is currently traveling between two anchor nodes.

3. **PRIORITY RULE:** If the narrative does not explicitly mention the party leaving, traveling, or arriving somewhere new, carry forward the PREVIOUS LOCATION and PREVIOUS STATE.
   - If the previous state was TRANSIT and there is no clear arrival, keep TRANSIT with `distance_traveled_km: 0` unless the prose demonstrates continued movement.
   - Do not assume movement just because a new landmark is mentioned in the distance.

3b. **INDEX RULE:** Return location changes as `location_events`, each with the zero-based `line` where that location state begins.
   - If there is no obvious location change inside this chapter, return exactly one event at line 0 using the PREVIOUS LOCATION and PREVIOUS STATE.
   - If the chapter begins somewhere different from the previous chapter, return an ARRIVED event at line 0.
   - If the party changes location mid-chapter, add another event at the first indexed line where the party is clearly in the new place.
   - If a background selector signal marks the same transition, try to match that same line index.
   - Do not create multiple events for local walking inside the same anchor node unless the specific location meaningfully changes.

3c. **TRAVEL ANIMATION PARTY RULE:** For each location event, return `travel_party`: an array of character names who are visibly or narratively moving with the party at that point.
   - This is ONLY for the pretty travel animation and must NOT be treated as character-location tracking.
   - Prefer names from TRAVEL ANIMATION CHARACTER CANDIDATES.
   - Include the player character only if they are clearly part of the traveling group.
   - Exclude distant, mentioned, minor, generic, absent, or stationary characters.
   - If no specific traveler list is clear, use the main party implied by the scene.

4. For "STAYED" or "ARRIVED":
   - Identify the "specific_location" for the party (e.g., "The Rusty Tankard Tavern").

4. If "TRANSIT", return `destination_mention` using the narrative's place wording and estimate `distance_traveled_km` for movement shown during THIS chapter only.

   - Use ACTIVE ROUTE PROGRESS as the odometer for an accepted route: it gives total, already traveled, and remaining distance before this chapter.
   - If ACTIVE ROUTE PROGRESS includes accepted narrative travel time / narrative route pace, use that story-space pace for elapsed-time progress on the accepted route instead of normal realistic walking pace.

   - If the narrative states route progress such as "halfway there" or "almost there", convert that to a target cumulative distance, subtract the already-traveled distance, and return only the additional distance for THIS chapter.
   - If travel clearly occurred but distance and duration are vague, make a conservative distance estimate in the preferred narrative unit, then convert it to the internal kilometre field.
   - If the party remains on the journey but this chapter does not demonstrate advancement, return `distance_traveled_km: 0`.

   - Never return coordinates. The tracker calculates the new physical position deterministically.
