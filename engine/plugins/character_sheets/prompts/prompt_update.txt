### EDITING RULES
- Only edit mutable sections.
- Do not modify sections marked [READ-ONLY].
- Do not update immutable baselines with temporary state.
- Put current outfits, grooming, injuries, dirt, blood, damage, and newly discovered persistent visual details in APPEARANCE & OUTFIT CONTINUITY, not baseline appearance/clothes.
- Keep changes concrete, direct, and grounded in the provided history.
- Before changing APPEARANCE & OUTFIT CONTINUITY, cross-check the proposed change against the existing sheet, especially PHYSICAL APPEARANCE, CLOTHES, HIGH-LEVEL SUMMARY, and BACKGROUND LORE.
- Treat the existing sheet as authoritative for species, anatomy, baseline body traits, and default wardrobe.
- Do not add a new physical/anatomical trait that heavily contradicts the existing sheet unless the recent history explicitly states a physical transformation, injury, mutation, disguise, costume, or newly revealed fact.
- Do not infer biological/anatomical traits from style cues, cosmetics, metaphors, preferences, or silhouettes. Example: "cat-ear hairstyle" does not imply actual animal ears or a tail.
- If the evidence is ambiguous, preserve the existing sheet and make no patch.
- Preserve the specificity of source facts. Do not broaden, euphemize, sanitize, or relocate precise details; keep named body regions, objects, speakers, targets, textures, timeframes, and persistence markers when the history provides them.
- Do not convert one physical feature into another. If the history says a localized or specifically qualified feature, keep that qualifier; do not collapse it into generic words like "hair", "skin", "clothes", or "accessory" when that changes the meaning.
- Do not invent decorative subdetails. Details such as sides, tips, exact length, color, scent, texture, styling, exact placement, and cleanliness must come from the recent history or the existing same layer.
- Do not blend baseline traits into new continuity facts. Baseline appearance can help identify the character, but it must not be used to embellish a newly learned detail.
- Do not add purple prose, vague metaphors, or generic summaries.
- If nothing meaningful changed, output no patches.

### PATCH FORMAT
To update the sheet, use one of these SEARCH/REPLACE forms.

#### Exact Text Anchor
Use this when you need a small, precise replacement inside a field:

<<<<<<< SEARCH
(Original text to find)
=======
(New text to replace it with)
>>>>>>> REPLACE

#### Field ID Anchor
Use this when replacing an entire mutable field. This is preferred when the old field is long or needs compaction:

<<<<<<< SEARCH
[field_id]
=======
(New complete value for that field only)
>>>>>>> REPLACE

- Field IDs are listed in the FIELD SCHEMA as "Field id".
- The replacement is the complete value for that one field, not an append note.
- Do not include the LAYER header, field label, or field ID in the replacement text.
- Preserve still-relevant existing facts while removing repetition and stale wording.
- Do not use field anchors for READ-ONLY sections.

- To DELETE text, leave the REPLACE block empty.
- To ADD text, include enough surrounding context in the SEARCH block to uniquely identify the location.
- Output only SEARCH/REPLACE patches. Do not add comments, intros, analysis, or assistant remarks.
